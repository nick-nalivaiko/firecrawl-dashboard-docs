No prior scraping knowledge assumed

Firecrawl is a pipeline from the web to usable data.

A search engine shows links. Firecrawl can discover sources, open them, remove navigation and ads, traverse related pages, and return a format that software or AI can consume.

Explore the featuresOpen the user guide
More than another Google

Firecrawl is valuable after a URL is found: it retrieves and normalizes the material. Search combines discovery with extraction, while the platform extends to crawling, structured data, documents, and browser flows.

01Discover

Search or Map finds the right addresses.

02Retrieve

Scrape, Batch, or Crawl fetches content.

03Normalize

Markdown cleans text; JSON maps facts to fields.

04Use

Compare, monitor, detect changes, or ground AI.

Features in plain language

What each tool actually does

Choose the scale of the job first. Each tool below includes three practical examples.

1 URL

Scrape

Read one page

Give it an exact URL and receive cleaned Markdown, HTML, links, a screenshot, or JSON.

  • Capture price and specifications from one product page.
  • Give an AI the article text without menus and banners.
  • Check whether a known pricing page changed.
URL LIST

Batch Scrape

Read known pages together

Runs Scrape as a job for a prepared list of independent addresses.

  • Compare 30 competitor pricing pages.
  • Collect 100 preselected job descriptions.
  • Refresh a specific supplier catalog.
SITE / SECTION

Crawl

Follow related links

Starts at one page and traverses a bounded site area to build a content corpus.

  • Collect product docs for an internal assistant.
  • Analyze a competitor's blog section.
  • Archive a help center before migration.
STRUCTURE ONLY

Map

List the pages

Discovers site URLs without downloading the full body of every page.

  • Find all documentation URLs under `/guides/`.
  • Understand a competitor's categories and landing pages.
  • Prepare a precise Batch Scrape list.
UNKNOWN URLS

Search

Discover sources and retrieve content

Returns search results and can retrieve cleaned full content in the same call.

  • Find current SaaS comparisons and read them immediately.
  • Collect sources and relevant passages for an article.
  • Find official pages for a technical error and pass the content to AI.
DEFINED FIELDS

Extract / JSON

Normalize pages to one schema

AI maps different page layouts into fields such as plan, price, country, requirement, or contact.

  • Build a plan/limit/trial table from pricing pages.
  • Extract author, date, claims, and sources from publications.
  • Normalize visa requirements from official country sites.
PDF / OFFICE

Parse

Read a document

Extracts content when the source is a file rather than a normal HTML page.

  • Turn a public PDF report into analyzable text.
  • Extract sections from a vendor manual.
  • Build a searchable corpus from tender documents.
BROWSER ACTIONS

Browser / Interact

Operate a dynamic page

Used when content appears only after a permitted click, wait, or scroll. This is a Firecrawl Cloud capability and is not part of the standard self-hosted stack.

  • Open a public table loaded by a button.
  • Capture your own test form after a scenario.
  • Read a public app screen after allowed navigation.
MULTI-STEP GOAL

Agent

Plan bounded research

AI chooses a sequence of web steps for an open-ended goal. Firecrawl Agent and its Spark models belong to Firecrawl Cloud; the connected Ollama profile does not replace them.

  • Compare solution options and cite evidence.
  • Confirm a claim across independent sources.
  • Build a market overview with explicit criteria and a request budget.

Different tools, different jobs

Firecrawl, Tavily, Serper, and Exa

The key distinction is whether you need ranked results, semantic discovery, concise agent context, or a controllable extraction pipeline.

ServiceStrengthChoose it whenTradeoff
FirecrawlSearch + extractionSearch, full content, Scrape, Crawl, Map, JSON, and browser workflows in one API.You are building a corpus, monitoring system, or RAG pipeline and need consistent output after discovery.It is more machinery than a task that only needs Google positions.
TavilyAI-oriented searchRelevant chunks, filters, dates, domains, optional answers, and raw content.An agent needs fast research context without managing a full crawler.A systematic site-section crawl remains a different job.
SerperGoogle SERP APIFast organic, news, images, maps, places, shopping, scholar, and other Google result types.You need ranking, localization, snippets, or Google-specific surfaces.A SERP response is not the cleaned full content of the result pages.
ExaSemantic discoverySemantic search, highlights, contents, entities, and research endpoints.You need conceptually similar documents, companies, or research beyond exact keywords.Site-wide traversal and deterministic processing of your own URL list may need a crawler.
A useful shorthand

Serper tells you what Google ranked. Tavily and Exa help an AI discover relevant sources. Firecrawl also answers how to retrieve and normalize those sources into a working dataset.

AI works on grounded material

How AI helps inside Firecrawl

Firecrawl first gives a model a bounded, cleaned source. The model can then structure or summarize against that evidence.

Structuring

Extract and JSON turn varied layouts into fields that code can validate.

Summarization

A model shortens long documents while retaining source links.

Crawl planning

Crawl Preview turns a plain-language description into bounded crawl parameters.

Knowledge preparation

Clean Markdown and metadata become grounded context for RAG and internal search.

Where the configured Ollama profile is used

Ollama is used for Extract/JSON, Summary, and Crawl Preview. Plain Scrape, Search, Map, Parse, and Research work without Ollama; Research calls OpenAlex and GitHub. Firecrawl Agent and Browser are separate cloud capabilities. READY provider status must still be allowed by the current project's AI policy.

Where the leverage appears

Five high-value workflows

The payoff comes from combining collection, structure, repetition, and AI.

01

Competitive intelligence before building a site or product

Map the pricing, features, cases, integrations, and blog areas of 15–30 competitors. Crawl only selected sections, normalize audience, offer, proof, pricing, and limitations, then use AI to identify repeated claims and unmet questions.

Competitor mapSelective collectionComparable schemaStrategy brief

Outcome: information architecture, positioning, and the editorial plan are based on a traceable page corpus rather than a few tabs or model memory.

02

A living country, market, or program requirements database

Search identifies official sources, Scrape and Parse read web pages and PDFs, Extract normalizes requirements, and monitors flag changes.

Official sourcesHTML + PDFFields + effective datesChange notification

Outcome: every fact has a source and verification date, and AI explains differences without replacing the primary document.

03

A technical assistant over multiple documentation sites

Crawl allowlisted official docs, add public PDF manuals through Parse, and index the cleaned Markdown. The assistant retrieves from this corpus and cites pages.

Allowlisted docsBounded CrawlKnowledge indexCited answers

Outcome: developers search one current corpus instead of many sites, reducing dependence on stale general model knowledge.

04

A radar for relevant projects and opportunities

Search allowed public sources, Batch Scrape details, Extract budget and requirements, then rank against verified experience. Keep proposals, messages, contracts, and money actions human-controlled.

Allowed sourcesNormalized listingsVerifiable criteriaHuman review queue

Outcome: a person reviews a short evidence-backed queue rather than hundreds of pages.

05

Monitoring product and infrastructure dependencies

Scrape and JSON snapshot pricing, status pages, changelogs, and dependency docs. A monitor reruns checks; a webhook carries a meaningful change into your workflow.

Critical pagesStructured snapshotVersion comparisonEvidence-backed alert

Outcome: teams learn about a removed API, changed price, or new requirement before it becomes an incident.

Possible, but inefficient

Five cases where Firecrawl is a poor fit

1. An official API exists

Use it for payments, CRM, weather, market data, or administrative records. It provides stable schemas and permissions.

2. You only need Google positions

A SERP API is simpler. Add Firecrawl only when you need the result pages themselves.

3. The data is already yours

Read your database, export, or internal API instead of scraping your own UI.

4. You need second-level realtime

Trading data, telemetry, and chat events need streams or webhooks rather than periodic crawling.

5. A person needs one page once

Automation pays off when the workflow repeats, scales, or feeds another system.

Stop before execution

Five cases that must be blocked

These conservative product boundaries reduce account bans, leaks, harm, and violations of source rules. Ambiguous commercial use still needs separate legal review.

1. Authenticated areas without permission

Do not use someone else's cookies, credentials, sessions, or bypass a paywall. Use an authorized API or export.

2. Instagram/Meta and services prohibiting automated collection

Public visibility is not permission to crawl profiles. Use the official API or express permission.

3. CAPTCHA or access-control circumvention

A block is a signal to stop, not to disguise the crawler or escalate proxies.

4. Sensitive personal-data harvesting

Do not collect credentials, private messages, medical, financial, biometric, or stalking-oriented profile data.

5. Attack-like load

Do not run unbounded crawls, excessive concurrency, or loops that can degrade another service.

robots.txt is not the whole permission model

It does not override site terms, copyright, privacy law, or contracts. It remains an important machine-readable instruction that crawlers should honor.

Product follow-up

Block unsafe requests before Core sees them

A central policy layer should apply equally to the UI and gateway so a direct API call cannot bypass a form warning.

1 · NormalizeParse URLs, IDNs, redirects, and final IPs.
2 · NetworkReject localhost, private ranges, metadata endpoints, and internal names.
3 · DomainsDeny prohibited platforms; require allowlists for sensitive projects.
4 · PolicyCheck robots rules, operation type, depth, concurrency, and rate.
5 · ExplainReject before spending resources and show a reason plus a safe alternative.

A safe first workflow

Start small and observable

  • Scrape one public page you are allowed to process into Markdown.
  • Verify the main text, links, and metadata.
  • Map the same domain with a small limit to understand structure.
  • Batch Scrape 3–5 selected URLs instead of starting an unlimited Crawl.
  • Only then add a JSON schema or AI summary and compare it to the source.
